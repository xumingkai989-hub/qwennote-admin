# T2：标签与分类文件渲染

`app.kb.build(store, root, tags=None)` 先渲染所有标签及非空分类，再调用 `build_index`。本票的 `tags` 参数仍为预留参数，始终全量构建；T1 的索引结构、统计、路径分配和 `content_hash` 口径保持不变。源数据库只读，不调用迁移、模型、会议更新或看板生成。

`render_tag_file(store, tag, notes=None)` 接收 `scan` 返回的标签字典。`notes` 本票为空，普通标签固定输出「综述未生成。」和「暂无补充记录。」。虚拟「未分类」保留标题、元信息，只输出会议与时间线两个章节；已有真实同名标签依 T1 分配不同路径并分别取数。

- 会议归属解析合并标签和别名，列表里的标签保留关联表原名称及 position 顺序。主议题来自 `recording_primary_tag.tag_name`，缺失显示 `—`。
- 会议按 `created_at` 的实际时间点倒序，同一时间按会议 ID 倒序稳定排序。日期用上海时区显示。会议最多 20 场，超出显示剩余场数；时间线最多 30 场。元信息仍是全量场次和分钟数。
- 总结保留到首个 `。`、`.` 或换行，保留句号；没有分隔符时取前 60 字。提取结果超过 80 字时保留前 80 字并加 `…`。空总结显示 `（无总结）`，NULL 时长显示 `时长未知`，零时长显示 `0 分钟`。
- 标题、标签、摘要进行 Markdown 文本转义，原文链接对会议 ID 做 URL 编码。

`render_category_file(store, category, tags)` 使用 T1 的分类去重统计。标签链接遵循本票明确指定的 `tags/<slug>.md`，以知识库根目录为路径基准；空格及括号用 Markdown 尖括号目标语法保护，`#` 和 `%` 编码，沿用 T1 对大小写、中文及重名后缀的处理。因此 `AI Tutor` 的链接为 `[AI Tutor](<tags/AI Tutor.md>)`。普通 Markdown 查看器若以 `categories/` 为相对路径基准，需要由读取端按知识库根目录解析此约定。

无标签分类保留在索引中，不创建正文。重复构建的标签和分类内容一致；索引仅构建时间更新。本票未实现内容未变时跳过写盘、增量构建或删除陈旧文件，这些不改变本票的正文渲染与 T1 统计口径。

`tests/test_kb.py` 增加 25 项用例，覆盖三场会议、20/25/35 场边界、总结首句与截断、缺失字段、未分类、别名合并、时区排序、分类路径与去重统计、Markdown 转义，以及重复构建和数据库只读。生产验收使用 SQLite backup API 创建独立副本，检查构建前后的逻辑摘要、源统计、文件数量和两次正文一致性。验收文件保存在仓库外私有目录，不提交会议内容。
