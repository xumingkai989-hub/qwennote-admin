# 工单 33：同步性能内核

`list_my_minutes` 的分页和转写分页统一使用 `nextToken`。2026-11-02 生产实测表明，录音列表会忽略 `cursor`、`pageToken` 和 `token`，重复第一页；重复游标继续抛出既有错误，避免死循环。

详情不再默认调用 `get_minutes_basic_info`，也不再将其列为必需工具。`get_detail(recording_id, meta=...)` 使用列表元数据的 `media_type`；没有 meta 时允许为空。每条仍按总结、转写的顺序拉取。

详情按每批最多 3 条提交到唯一的 `ThreadPoolExecutor(max_workers=3)`，每批结果按 `recording_id` 关联，所有 SQLite 查询、写入和计数在调用线程完成。提交前去重、检查快速同步跳过条件。单条失败保留安全错误，其余条继续入库；OAuth 续期失败沿用现有整轮认证错误处理。批次完成后再提交下一批，避免降级时仍有积压请求。

详情 HTTP 429 / 5xx 转为不含响应正文的状态异常，由录音级统一最多尝试 3 次，等待 1 秒、3 秒，加 0–250 毫秒随机抖动。MCP 传输层不再对这些详情状态另行重试，避免重试预算相乘。连续 3 条重试耗尽且最终状态为 429 后，完成当前批次，并将后续详情改为串行；成功或其它错误打断连续计数。已经提交的当前批次最多 3 条。`detail_serialized` 持久记录降级，CLI、结果页和日志均可观察。

`sync_runs.duration_ms` 为整数毫秒，使用单调时钟记录取得同步锁后到完成同步的墙钟耗时；包括列表、详情、退避、入库和既有 AI 增强阶段。迁移幂等，历史行默认为 0。保留原先先记录同步结果再执行热词判断、打标的时机，增强结束后回写最终耗时与结束时间。没有新增第三方依赖。

## 验证与测量

新增测试覆盖 45 条跨 3 页、重复游标、基本信息零调用、3 个线程确实重叠、10 条全部入库、单线程写库、乱序完成正确关联、失败隔离、429/500/503 重试预算和抖动、连续限流降级、非连续失败不降级、重复 ID 幂等、旧库迁移、包含增强阶段的耗时及页面展示。共享 MCP 源的初始化和请求编号加锁，测试验证并发初始化只发生一次且 RPC 编号唯一。

部署前后在同一实例上，用同一份 SQLite 备份和固定上游时间窗口实测；ID 集合哈希验证输入一致。测试数据库均为独立副本，不删除生产录音。旧版全盘先记录真实分页失败，再仅在测量脚本中替换正确的分页函数，以测量其串行详情路径。单条新录音用全窗口扫描、其它 20 条走跳过逻辑模拟，仅候选条调用真实详情接口；原始备份保留。

生产实测结果另附本工单交付报告；所有上游失败和未完成场景均如实记录。
