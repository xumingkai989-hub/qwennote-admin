# UI 文案原则：让布局自己说话

> Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.

后续所有 UI 工单以此为准。

1. **重复布局含义的文案，删。** 控件已经说明的事（日期选择器的用途、分段控件的选项、图标按钮的功能）不再加文字。
2. **只允许四类说明文字存在：** ① 防误解的口径；② 空状态；③ 错误原因与下一步；④ 危险操作确认。
3. **删除前自问：删掉后用户会不会做错事？** 会 → 保留，但要压到最短。

## 如何判断

先区分内容、操作名称与附加说明：标题、数据、状态、必要字段名和无障碍名称是识别与操作所需，不应机械删除。
对每句附加说明，先看布局或控件是否已表达相同含义，再判断是否属于四类例外，并问删掉是否会导致误操作。
重复且无风险就删除；必要但冗长就压缩；缺少它会误解或无法继续就保留。
删除后连同失去用途的容器、引用和空分隔线一起清理；用正常、空、错误状态及桌面、手机视口验证。
