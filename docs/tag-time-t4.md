# T4 每日生成与周度 AI 解读

每日 board 任务、管理员生成和写入式 CLI 统一调用 `board_generation.generate`。周度顺序为补齐主标签、计算本周分配、生成并存档解读；原有 `board_analysis` 函数保持不变，仅新增 `week_allocation_text`。`--print` 仍只读，不判定标签或写库。

`week_allocation_text(allocation, previous=None, *, model=None)` 的 model 为接收 JSON 输入、返回 JSON 字符串的可调用对象；生产编排器绑定现有数据库模型配置，无模型返回 None。代码按分钟降序取最多三个非零分类，用 allocation.share 转换百分比（最多两位小数）；上周使用完整自然周的只读分配。代码预先计算绝对变化最大的两个分类及百分点，模型只能选择给定分类，最终正文由代码拼接。未知分类、非法 JSON、建议等自由文本拒绝；无上周数据的结尾固定为「上周无对比数据」。不向模型委托数字运算，也不自动补判历史周。

原周度会议回顾保留，时间分配正文追加到 `board_reports.analysis_md` 的「时间分配」段。页面将该段放在当前周分配模块末尾；原会议回顾区不重复展示。分配模块的管理员「重新生成」复用既有表单、权限和 CSRF，日期固定当前日，历史日报浏览不会误生成其他周。未生成时显示「解读未生成」。今日分析提示词、统计字段与周度按天柱状图不变。

新增 `board_generation_state` 作为独立缓存表，原 `board_reports` 七列及其语义不变。复合键为 day + scope，保存输入摘要、存档摘要、最近有效分配和当前解读状态。数据库旁的文件锁串行协调进程与线程，防止同时点击重复调用模型。同日同截止日、会议材料、标签判定、分配、上周对比及数据库默认模型配置不变时，复用成功结果；材料变化失效，模型失败允许再次生成。每日调度不能仅凭新鲜日报跳过尚未生成的周度分配。

主标签失败不阻断聚合，error 写入「主标签判定部分失败」，未分类仍计入。聚合异常或守恒失败时，整块标记「时间分配计算失败」，数字回退同周最近有效快照，没有快照则不画图；读取页面也有相同保护。恢复后需重新生成解除失败状态。解读失败清空该解读段，保留数字和独立的会议回顾。分配实时变化后不展示与当前数字不匹配的旧解读。

## 验证与发布

全量 Python 1691 项通过（T3 基线 1664 + 本票 27），一个已有依赖弃用警告；JavaScript 交互回归 43 项、看板浏览器回归 12 项通过。

新增 27 项 Python 测试：顺序、真实判定调用计数、重复/重启/并发幂等、材料变化、占比与环比、非法模型输出、失败回退与恢复、当前周和历史隔离、调度入口。既有测试适配新编排入口、周报追加错误及新增表清单，保留原断言意图。浏览器样本走真实生成和存档链路，仅替换模型为离线响应，核对正文、日期、390/1440 布局及图表交互。

发布沿用现有依赖，复制当前 release 后覆盖已提交文件，仅执行 app-only activate；备份数据库并核对宿主配置哈希，不执行 prepare，不改 `.scratch/`、nginx 或 `/etc/`。新增表可保留后回滚旧版，不需要恢复覆盖业务库。测试日志、release、真实生成与私有 HTML 说明保存在仓库外交付目录。业务报告未获公开授权，不上传公共存储。
