# 工单 37：标签词表两级分类

`tags.category` 默认「其他」，`tag_categories` 管理分类名称、顺序与启用状态。首次建表写入产品（1）、公司管理（2）、中台（3）、师资（4）、市场（5）、技术（6）、其他（99）；后续迁移不覆盖管理员调整。运行时分类与提示词完全从数据库读取。

AI 响应为 `{"tags":[{"name":"模考系统","category":"产品"}]}`。兼容旧字符串响应或缺失分类，回退到兜底分类；未知分类先由模型映射到已有分类，模型不可用时按名称近似匹配，无法匹配则回退。不会自动创建分类。新标签和分类在打标事务中一起入库，已有标签的分类优先；按分类组织提示词，反馈指令原样保留。

`/assistant` 的分类默认展开，可独立折叠；点击分类名修改名称，归属下拉选择即时保存并移动到对应组。失败恢复旧选择并显示提示。新增、改名、停用均要求管理员与会话绑定的 CSRF。停用是可恢复状态，保留分类和全部标签，并继续参与打标；标签本身的停用行为不变。合并及别名链沿用最终目标的分类。列表、详情、搜索模板未改动。

## 首次上线回填

先备份数据库并完成 schema 迁移。使用生产现有模型配置运行下面命令；不要把网络调用放到 `store.migrate()` 或请求启动路径。

```sh
cd /opt/qwennote/current
runuser -u qwennote -- env DB_PATH=/opt/qwennote/data/qwennote.db LD_LIBRARY_PATH=/opt/qwennote/current/.sqlite/lib .venv/bin/python -m app.tag_categories
```

模型中心默认模型优先，复用应用的模型环境后备配置。命令逐标签请求模型，输出 attempted/succeeded/failed/deferred 与分类结果。未配置模型、请求失败或响应不合法时退出非零，保留默认值和待处理状态，可以重跑。成功项及管理员手动分类通过 `tag_category_checks` 留存，重跑不覆盖；分类任务使用既有 tag lock 串行，模型请求期间不持有 SQLite 写事务。

兜底分类通过首次迁移固定种子 ID 识别，因此管理员改名后仍可正确接收无分类的新标签。分类管理使用停用替代物理删除。
