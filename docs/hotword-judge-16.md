# 工单 16：模型判断后替换与撤销

热词替换在展示层按 `(recording_id, hotword_id, field)` 的 `apply` 决策生效。未判断、`skip`、停用、已删除的热词均不替换；数据库原文、标题和搜索索引不受影响。手工编辑覆盖正文继续优先展示，不再叠加热词。

`recording_hotword_decisions` 保存 summary / transcript 的 apply / skip、reason 和 decided_at，复合主键确保覆盖写幂等。迁移仅新增决策表和计数索引。热词原词或替换词变更会删除对应旧决策，备注变更保留决策；删除热词清理对应决策。同步新增或总结、转写、正文有效性变化时执行判断；内容变化与清除旧决策在同一事务内，判断期间按未判断展示原文。

每条记录最多一次 Anthropic Messages 请求，复用模型中心默认模型与原环境回退配置。候选按热词和字段打包，发送 A、B 和原词最多三处上下文，每处前后各 40 字。先去掉 origin 标记，与展示管线顺序一致；大小写不敏感，特殊字符按字面匹配。没有上下文或无效正文的字段本地记录 `skip / no_occurrence`，不调用模型。

系统提示要求只有 A 确实指代 B 所述事物才 apply，不确定、混用、人名同音或普通词重名时 skip；输入内容仅作数据。模型以严格 JSON `{"decisions":[{"hotword_id":1,"field":"summary","decision":"apply","reason":"确指该产品"}]}` 返回批内每项。要求完整覆盖候选、唯一键、合法 ID / 字段、apply 或 skip 及最多 30 字理由，禁止额外字段、重复 JSON 键或 Markdown 包裹。任何请求错误、HTTP 失败、超时（整条记录 30 秒）、非法 JSON、缺项或非法理由均将该次所有候选记为 `skip / judge_failed`，不重试，不替换。不存在匹配的项仍保留 `no_occurrence`。

判断写入时重新核对录音正文和有效性、热词版本以及旧决策快照。请求期间内容、规则或手动撤销改变则拒绝写入，避免迟到响应覆盖用户撤销或将旧判断用于新正文。判断进程使用独立数据库文件锁串行；展示和撤销不等待模型请求。

详情页未判断时显示「本条的用词尚未经过热词判断」。有替换时显示可展开的「热词已应用 N 处」，计数来自两个字段实际替换次数（沿用最长优先、单遍替换和 Markdown 保护），展开列出原词 → 替换词、字段、次数和理由。每个热词 / 字段提供撤销，若同词出现多次，按钮一次撤销该字段全部对应替换，符合决策主键粒度。管理员撤销写入 `skip / manual_revoke`，303 返回当前详情，立即恢复该字段原词。其他字段的决策不变。热词中心按仍启用的 apply 决策统计不同记录数，同一记录两个字段只计一次；有手工覆盖的字段不计。所有写操作复用现有活动管理员与 `recording_csrf`，禁止缓存。

详情、分段 Markdown 导出、单条 API 和日报 Markdown 共用按记录和字段过滤的展示管线。无记录或字段身份调用替换函数也保持原文，禁止回落到全表替换。命中次数继续按实际展示 / 导出累加，留痕面板计数不增加累计命中。

## 手动补判与部署

```sh
# 在已经加载 DB_PATH 和模型环境的应用环境运行
python -m app.hotword_judge --all
# 明确重新判断（会覆盖已有 skip，包括手动撤销）
python -m app.hotword_judge --all --force
```

`--all` 补齐所有记录缺失的决策，保留已有 apply / skip 和手动撤销；失败决策需要显式 `--force` 才重试。重复强制判断仍覆盖写，不增加行。命令输出每条记录 apply / skip / judge_failed 数量；这些是热词 / 字段决策行数，不是文本出现次数。请求失败或快照冲突退出非零，录音同步本身继续完成。

部署用 `python3 scripts/deploy.py --app-only`，保留 previous 并核对全部 nginx conf 哈希。对现有十条记录执行一次 `--all`，比较判断前后 `recordings` 全行摘要验证原文未改。回滚旧 release 会恢复旧版本无条件替换行为，故需要回滚时应先停用热词。决策表可保留供新版本再次使用。
