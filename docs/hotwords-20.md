# 工单 20：标准词与逐条推送

热词只保存标准词及备注。SQLite 使用 `BEGIN IMMEDIATE` 内重建表，废弃内容直接丢弃，不转存备注、审计或其他表；旧格式迁移归档中的对应列也删除。热词保留 id、term、note、enabled、hits、created_at、updated_at、needs_review。任何迁移异常回滚；判断决策、录音原文和手动正文不受影响。迁移测试逐表检查唯一废弃内容哨兵不存在，并注入重建后异常验证旧结构及值回滚。

模型请求只给标准词和上下文，要求自行识别连续原文片段。span 仍为至多 12 字、无标点、原文真实出现且能唯一定位。采样仅依据标准词和文本；相邻窗口尽量以空白、标点分界，避免在英文单词内截断。重复且无法唯一定位的模型结果仍拒绝，合法结果按原有位置管线展示。

## 页面与接口

新增和编辑表单仅有「标准词（必填）」及「备注（选填）」。列表为标准词、备注、命中次数、千问、操作。编辑正文后的建议弹层和 `POST /hotwords/bulk` 也仅提交 `{term}`，不保存识别错误片段作为规则。

- `POST /hotwords/{id}/push-qwennote`：管理员、会话绑定 CSRF、同源保护；点击立即执行，无预演。字符限中英文、数字和普通空格；汉字至多 20、其余 ASCII 至多 40；停用拒绝。先读取实时配额，`currentCount >= maxCount` 拒绝新增。每次新增工具调用仅包含 `hotWordList: [term]`，不自动重试。
- 成功写 `hotword_upstream_sync(status=ok, upstream_value=term)`，时间记录实际完成。未变词的普通重复请求跳过，页面主按钮禁用显示「已推送」；「重新推送」显式传 `force=1`。编辑标准词后自动显示未推送；改备注保留推送状态。
- 失败写 `status=failed`；`hotword_upstream_errors(hotword_id,message)` 单独持久化错误摘要，同步表四列保持。工具 `isError`、JSON-RPC error 和 `success=false` 的消息去除凭据、截断 200 字，页面转义显示。网络错误使用已有安全摘要。再次成功清除旧错误。
- `POST /hotwords/sync-qwennote`：顶部「全部推送」直接串行执行每词流程，失败继续，返回逐词结果及「成功 N / 失败 M」。未变的已成功词跳过，不重复占配额。文件锁串行协调单条和全部请求。旧页面的 `confirm`/`plan_hash` 参数一律拒绝并要求刷新，避免旧预演误触发新增。
- 页面通过 JSON 返回值立即更新行状态及汇总，刷新后仍从数据库显示。页面加载只读取配额，不执行新增。上游导入继续显式勾选、逐个加入本地标准词，仅按标准词归一化查重。
