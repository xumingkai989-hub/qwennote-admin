# T4：标签 AI 综述生成与缓存

`build_summary_input(store, tag, max_chars=6000)` 取最近 5 条 SQLite 补充记录（日期、来源、正文）和最近 10 场会议（日期、标题、summary_md 前 200 字）。补充记录在前，同类记录倒序；会议归属沿用 T1–T3 的别名/合并解析。输入头部注明标签主题，避免把多标签会议中的旁支事项当作主线。长度包含主题、标题和分隔符，超限先逐场去掉最早的会议，再逐条去掉较早补充记录。自定义极小预算不足以放下最新一条补充时，才截断该条；负数拒绝，0 返回空串。无数据不调用模型。

`generate_summary(store, tag, model=None)` 复用模型中心解析和 `board_analysis.request_text`，model 可覆盖模型名称。系统提示词限定输入仅为数据、忽略其中指令，要求 3–5 句中文纯正文，说清推进事项、进展和卡点；不建议、不评价、不编造，不复述结构词和资料来源，不把测试性数据写入/重建验收当作业务进展；冲突时以补充记录为准。未提供的进展或卡点只能明确未说明；已经给出的卡点不能同时写成未说明。保留证据确定程度，不把讨论、介绍、规划改写成已完成/上线/集成，不自行添加阶段先后、功能归属或因果关系。提示词约束语义，不声称机械校验能保证模型绝无幻觉。

清洗复用现有五句截断器：删除 Markdown 标题/围栏行，去掉行首列表符和数字编号，合并空白，保留最多五句（不把小数点当句号），并去掉行内强调、代码及链接标记。不足三句不自动补写事实；正常生成的句数由提示词约束。渲染继续转义 Markdown/HTML，失败或空输出写「综述未生成。」。

缓存使用独立 SQLite `knowledge_summary_cache` 表，字段为 `tag_name, input_hash, summary, model, generated_at`，主键 `(tag_name, input_hash)`；input_hash 是完整组装输入 UTF-8 的 SHA-256。迁移幂等，仅新增表，不更改 T1–T3 的索引结构、content_hash 或补充记录逻辑。成功清洗后才写入，缓存查询在解析模型配置之前，因此同输入再次构建无需模型或密钥。输入变化重算，失败不返回旧输入的缓存；失败不缓存，下次可重试。模型名称变化本身不触发重算，符合本票仅按输入文本失效的合同。

普通标签的「当前状态」接入生成结果；虚拟「未分类」保留 T2 的章节结构。单标签模型、配置或缓存异常均退化为未生成，不阻断其他标签及补充记录/会议渲染。没有新增第三方依赖，没有新增 CLI 或定时任务。

专项测试覆盖正常渲染、10/5 条限制、200 字前缀、6000 字预算与删除优先级、提示词冲突/数据边界、异常隔离、空响应重试、迁移后缓存命中、模型覆盖、标题/总结/补充新增/删除/来源触发失效、未纳入输入的总结尾部不触发重算、旧缓存失败隔离，以及 Markdown 清洗和五句截断。

发布沿用前一 release 的运行依赖，仅覆盖本票提交文件，执行 app-only activate；不运行 prepare，不修改 `.scratch/`、nginx 或 `/etc/`。真实综述及会议输入只保存在仓库外私有验收目录，不进入 Git 或公开对象存储。
